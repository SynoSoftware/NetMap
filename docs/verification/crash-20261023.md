at 16:17:42. This precedes the current executable's 16:26:43 write time. The
earlier Settings work separately localized an empty-label measurement stall and
added a guard before DrawText; without an exception stack, that observation is
not proof of this access violation's cause. No usable NetMap dump was found in
the inspected WER report/archive and per-user CrashDumps locations.

The current executable was checked again with:

```powershell
.\tests\native-settings.ps1 -Executable .\target\x86_64-pc-windows-msvc\debug\netmap.exe -EvidenceDirectory V:/temp/netmap-crash-recheck-20261023-a
```

after 17:00. No NetMap or WerFault process remained after the check.

## Isolated mechanism reproduction

`V:/temp/netmap-empty-drawtext-proof.ps1` reproduces the native call with the
same measurement flags (`DT_CALCRECT | DT_WORDBREAK | DT_NOPREFIX`) in a
disposable hidden process. Each child has a ten-second external limit and sets
only its own `SEM_NOGPFAULTERRORBOX`; no product/global WER setting changes.

- Valid allocated empty text, count 0: normal exit; rectangle bottom 0.
- Valid text, count 1: normal exit; rectangle bottom 16.
- Pointer `0x2`, count 0: fatal `0xc0000005` inside `DrawTextW`, before return.

An empty Rust `Vec<u16>` can supply that aligned dangling pointer. The inspected
windows 0.62.2 binding forwards the slice pointer and length directly. Thus a
zero length does not make this native call safe. The current `wrapped_height`
guard already skips empty buffers; it was present in the 16:26 executable and
was not newly introduced in response to this report.

The proof source and bounded stdout/stderr are retained under
`V:/temp/netmap-empty-drawtext-proof.ps1` and
`V:/temp/netmap-drawtext-{DanglingEmpty,ValidEmpty,Text}.{out,err}`. The final
source delta adds a comment preserving this native constraint and an actual
hidden STATIC-control regression for empty -> populated -> empty text. Its
independent review is clean in the merged Settings layout review record.

Status: the empty-buffer crash mechanism is reproduced and the existing guard
prevents that call. Attributing the historical NetMap exception to this exact
site remains a strong inference without the original exception stack. The
successful current journey is not proof against every callback/lifetime defect.
